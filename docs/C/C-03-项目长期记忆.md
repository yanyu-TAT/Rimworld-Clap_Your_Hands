## 二、架构决策记录

### ADR-1：零 Harmony 补丁（重要）

**决策**：本项目不使用 Harmony 补丁，全部功能通过原版扩展点与 Def 实现。

**理由**：RimWorld 1.6 的社交互动系统已提供完整扩展点——`InteractionDef` + `InteractionWorker` 会自动进入原版随机社交池，`Interacted` 是官方虚方法扩展点，`AddInteractionThought` 是 public static，Hediff 的 `stages[]` 可直接表达增益。补丁只会带来加载顺序风险与版本脆弱性。

**约束**：任何新需求先问「原版有没有扩展点/Def 字段能表达」，再考虑代码，**最后**才考虑补丁；引入补丁前必须先向用户确认。

**证据**：见 `docs/C/C-05-原版API简述.md` 一、社交互动系统。

### ADR-2：运行时状态用 Hediff 承载，禁止裸 static

**决策**：24h 冷却、12h 增益等随 Pawn 的状态一律用 `HediffDef` 承载。

**理由**：Hediff 随 Pawn 自动参与 Scribe 存读档，自动过期，天然多存档隔离；裸 `static Dictionary` 会在存读档后丢失或串档（`AGENTS.md` 高频错误 #3）。

### ADR-3：概率曲线用原版 `SimpleCurve`

**决策**：好感度 → 概率/权重的映射统一用 `SimpleCurve`（`Verse.SimpleCurve`）。

**理由**：原版 `InteractionWorker_DeepTalk` 即此范式（`0.075f × CompatibilityFactorCurve.Evaluate(...)`），点位即调参入口，避免手写阶梯 if-else。

## 三、命名与文本约定

- 新 Def 的 `defName` 统一以 `Clap` 前缀（如 `Clap`、`Clap_Bad`、`Clap_Buff`、`Clap_Cooldown`），保证全局唯一
- 代码内文本 → `Keyed`，键名格式 `ClapYourHands.<域>.<语义>`（如 `ClapYourHands.Clap.Perfect`）
- Def 内文本 → `DefInjected`，文件名与 `Defs/` 一一对应
- 中英语言文件**逐键对称**，不允许单边缺失

***

## 四、已核实的关键原版行为（易踩坑）

1. **没有「直接增加好感度」的 API** — opinion 是派生值，必须经 Social 型 `ThoughtDef` + `Pawn_InteractionsTracker.AddInteractionThought` 写入；且写入时会乘 `SocialImpact` 缩放，字面 +3/+5 不成立。
2. **`lastInteractionTime` 是 private** — 自定义互动的冷却只能自建载体。
3. **敌对已被原版排除** — `TryInteractRandomly` 中显式 `pawn.HostileTo(p)` 跳过；「仇视」需自己在权重里返回 0。
4. **社交距离上限 6 格** — `SocialInteractionUtility.MaxInteractRange = 6f`（含视线检查）。
5. **互动有 120 tick 硬下限** — 两次任意互动之间至少间隔 120 ticks（`InteractAndSocialFightIntervalAbsoluteMin`）；`InteractionDef.ignoreTimeSinceLastInteraction` 可跳过该检查。
6. **`Interacted` 之后原版仍会执行**：气泡生成 → 双方冷却时间戳更新 → `PlayLogEntry_Interaction` 入日志 → letter 发送，所以不要在这些环节重复做事。
