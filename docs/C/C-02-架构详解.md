# C-02 架构详解

> 系统设计细节与架构决策。原版 API 的具体签名与行为见 `docs/C/C-05-原版API简述.md`。

## 一、总体结构

本模组是一个**纯扩展式**模组：不干预原版流程，只在原版提供的扩展点上追加一个社交互动。

```
Defs/                        Source/                        原版
─────────────────────────────────────────────────────────────────────────
InteractionDef "Clap"  ──►  InteractionWorker_Clap
   workerClass                 ├─ RandomSelectionWeight()  ◄── Pawn_InteractionsTracker
                               │     └─ 触发权重 + 仇视排除      .TryInteractRandomly()
                               └─ Interacted()              ◄── TryInteractWith()
                                     ├─ ClapUtility.RollOutcome()     发生实际互动时
                                     ├─ AddInteractionThought()  ──► 情绪 + 好感
                                     ├─ Hediff_ClapBuff          ──► 12h 随机增益
                                     └─ Hediff_ClapCooldown      ──► 24h 冷却（双方）
```

## 二、互动生命周期（我们的代码何时被调用）

```
① 每 60 tick，原版为每个 pawn 掷「想不想社交」的 MTB
② 命中 → 遍历同派系已生成 pawn（Shuffle）
③ 对每个候选人：过滤（自身/不可互动/敌对）→ 对全部 InteractionDef 加权抽取
      └─► 我们的 RandomSelectionWeight(initiator, recipient) 被调用
          · 返回 0 → 本次不被选中（仇视/冷却在这里排除）
④ 抽中「击掌」→ TryInteractWith(p, Clap)
      · 原版门禁：距离 ≤6 格 + 视线 + 双方清醒未燃烧能说话 + 120 tick 硬下限
⑤ 无 initiatorThought/recipientThought（我们留空）→ 不自动加想法
⑥ 技能经验（initiatorXpGainSkill = Social）
⑦ 可能转打架（社交斗争）——转打架则跳过 ⑧
⑧ ─► 我们的 Interacted(initiator, recipient, ...) 被调用
      · 抽取四档结果
      · 写入情绪 / 好感度 ThoughtDef
      · 完美档：抽取并施加 12h 增益 / 灵感
      · 双方写入 24h 冷却
⑨ 原版继续：生成互动气泡 → 更新双方 lastInteraction 时间戳 → 写社交日志 → （我们返回 null 则不发信）
```

**要点**：`RandomSelectionWeight`（③）会被**大量高频调用**（对每个候选人都要算一遍），必须廉价、无副作用、不写日志；所有副作用只能出现在 `Interacted`（⑧）。

## 三、状态载体设计

| 状态 | 载体 | 生命周期 | 持久化 |
| --- | --- | --- | --- |
| 24h 互动冷却 | `Hediff_ClapCooldown`（隐藏） | 24h 后自动过期 | Hediff 随 Pawn Scribe |
| 12h 随机增益 | `Hediff_ClapBuff`（单实例） | 12h 后过期；被更高档覆盖 | Hediff 随 Pawn Scribe |
| 情绪 / 好感度 | 原版 `Thought_Memory` / `Thought_MemorySocial` | 由 `ThoughtDef.durationDays` 决定 | 原版记忆系统 |

**设计原则**：

- **每 Pawn 至多一个** `Clap_Buff`：等级用 `severity`（1/2/3）；时长交给原版 `HediffComp_Disappears`；合并规则（取最高 + 同级/高级覆盖时长）写在 `Hediff_ClapBuff` 类内
- **不使用裸 static 字典**保存任何状态（存读档会丢/串档）
- **定时失效一律用原版 `HediffComp_Disappears`** —— `SetDuration(int ticks)` 可**随时**修改持续时间，字段与存档序列化均由原版组件承担；不自己写 `Tick` / `ShouldRemove` / `ExposeData`（详见 `C-05` §7.3）

## 四、判定顺序（重要）

`RandomSelectionWeight` 内的短路顺序（从廉价到昂贵）：

```
1. 基础有效性（pawn 有效、非同一人）
2. 仇视判定：min(双方 opinion) <= MinOpinionToClap → return 0
3. 冷却判定：双方都在冷却中 → return 0（OR 口径；AND 开关见计划文件）
4. 返回 BaseSelectionWeight × WeightFactorByOpinion.Evaluate(opinion)
```

## 五、时序与边界情况

| 情况 | 处理 |
| --- | --- |
| `Interacted` 中 recipient 已死亡/被移除 | 入口校验后直接 return（校验排在副作用之前） |
| 抽取增益时 `GetRandomAvailableInspirationDef()` 返回 null | 按降级策略处理（见计划文件待确认项 2） |
| 双方中一人已有更高档增益 | 低档完全忽略（不影响等级与时长） |
| 互动转打架（social fight） | 原版不会调用我们的 `Interacted`，无副作用 |
| 互动发生在异派系（如访客） | 由原版门禁决定；`AddInteractionThought` 内部自行判空 |

## 六、为什么不写 Harmony 补丁

见 `docs/C/C-03-项目长期记忆.md` 的 ADR-1。简述：原版扩展点已足够覆盖本功能全部需求，补丁只带来加载顺序风险与版本脆弱性，且会让「击掌」与其它模组的同类补丁产生冲突面。
