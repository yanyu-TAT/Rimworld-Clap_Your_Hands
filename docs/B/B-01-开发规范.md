# B-01 开发规范（细则）

> 权威源为根目录 `AGENTS.md`。本文件是其细则展开与示例补充；两者冲突时以 `AGENTS.md` 为准。

## 一、零补丁原则的落地判据

新增一个功能前，按顺序自问：

1. 原版有没有 **Def 字段**能直接表达？（如增益 → `HediffStage.statFactors/statOffsets`）
2. 原版有没有**虚方法 / 扩展点**？（如互动结算 → `InteractionWorker.Interacted`）
3. 原版有没有**可调用的 public 静态工具**？（如加想法 → `Pawn_InteractionsTracker.AddInteractionThought`）
4. 以上都没有，且确实无法变通 → **先向用户说明再决定**是否引入补丁

## 二、Hediff 使用规范（本项目主力状态载体）

```
✅ severity 必须有正初值（initialSeverity > 0），0 会被立即移除
✅ 隐藏型 Hediff 用 isBad=false；需要不出现在健康列表时用自定义 Hediff 类配合
✅ 过期逻辑优先自维护（自定义 Hediff 内 Tick + ExposeData 存过期 tick），
   避免依赖未经核实的原版 API（如历史上不存在的 SetDuration）
✅ 增益类 Hediff 每 Pawn 至多一个，等级用 severity、时长用自定义字段，合并规则写在类内
❌ 用多个互相叠加的 HediffDef 表达「取最高」——会让 UI 与逻辑都变复杂
```

## 三、随机与概率

```
✅ 概率曲线用 SimpleCurve（点位即文档，便于用户调参）
✅ 权重数组与常量集中在文件顶部，并注明设计文档出处
✅ 抽取前先过滤权重为 0 的项；可抽项为空时直接返回默认档并记日志
❌ 手写阶梯 if-else 表达曲线
❌ 用重试循环实现「按权重抽取」
```

## 四、异常与日志

```
✅ 互动结算入口先做关键依赖校验（Def 引用、双方 pawn 有效性），校验排在副作用之前
✅ 日志统一使用 ClapYourHandsMod.LogPrefix 前缀，便于 Player.log 检索
❌ 吞掉异常；❌ 在互动结算中抛出未捕获异常（会污染原版调用栈）
```

## 五、Def 与 XML

```
✅ defName 全局唯一，统一 Clap 前缀
✅ 类名引用带命名空间前缀（hediffClass 等），但 InteractionDef.workerClass 按原版惯例
✅ 每个 XML 文件用 [xml](Get-Content <file>) 解析验证后再提交
✅ Def 内文本保留英文默认值，由 DefInjected 覆盖
❌ 在 Def 字段填 Keyed 键
```
